# analytics_module 需求規格

## 負責檔案
- `app/analytics.tsx`
- `styles/analytics.styles.ts`

## 功能描述
本模組實作「視覺化分析」頁面。使用者在此頁面中可以選擇特定病患，並選取該病患的任一筆腸音紀錄。頁面會展示高質感的模擬時域波形圖、頻域頻譜圖（Spectrogram 熱圖），以及對應的 AI 臨床診斷報告（包含腸鳴音次數、分類狀態與建議）。

## 輸入 / 輸出
- **輸入**：
  - 讀取 `patients` 列表與 `records` 列表。
  - 使用者下拉選擇病患與採集紀錄。
- **輸出**：
  - 渲染波形圖 (Waveform)、頻譜圖 (Spectrogram)。
  - 渲染 AI 診斷卡片與數值指標。

## 相依模組
- `context_module` (`context/AppContext.tsx`)

## 實作要求
1. **連動篩選選單**：
   - 提供兩個選擇器：第一個為「病患選擇」，第二個為「紀錄選擇」（顯示採集時間與長度）。
   - 當選取特定病患時，第二個選擇器會**即時連動過濾**，僅展示該病患的採集紀錄。
   - 若該病患無任何紀錄，紀錄選擇器應顯示「無採集紀錄」並提示去錄音。
2. **模擬波形圖 (Waveform) 繪製**：
   - 讀取 `aiResult.waveformMockData`（包含 50 個點的數組）。
   - 以精緻的視覺效果呈現：例如使用 React Native SVG（若有安裝）或高度自訂的 Flexbox 柱狀圖（Barcode-like waveform）或 Canvas 繪製平滑的時域曲線，展示腸音信號的能量起伏。
3. **模擬頻譜熱圖 (Spectrogram) 繪製**：
   - 讀取 `aiResult.spectrogramMockData`（10x10 的二維矩陣，數值在 0-255 之間）。
   - 在畫面上以 10x10 的網格 (Grid) 渲染成一個「頻譜熱圖」。網格中每個方格的顏色深淺（例如由冷色系藍色到暖色系紅色）代表該時間與頻率點上的能量強弱，模擬專業聲學頻譜。
4. **AI 診斷報告面板**：
   - 展示三個核心指標：
     - **腸鳴音頻率**：如 `6 次/分鐘`。
     - **狀態分類**：`正常 (Normal)`、`亢進 (Hyperactive)`、`減弱 (Hypoactive)`，並配以對應的主題顏色背景（綠、紅、橙）。
     - **信心度**：如 `94.5%`。
   - 底部顯示詳細的臨床診斷說明（例如：「此段音訊內腸鸣音頻率正常，波形規律，未偵測到明顯腸阻塞或發炎引起的亢進信號。」）。

## 測試要求

### 測試工具
- Expo Go 實機或模擬器手動操作。

### 測試情境

#### 測試情境 1：病患與紀錄連動篩選
- **輸入**：選取病患 `P-1002`。
- **預期輸出**：紀錄選擇器的下拉列表中，僅會出現屬於 `P-1002` 的紀錄選項（例如 R-2002，而不應出現 R-2001）。
- **允許偏差**：無

#### 測試情境 2：圖表渲染與數據一致性
- **輸入**：選取 `P-1001` 的 `R-2001` 紀錄。
- **預期輸出**：
  - 波形圖區域正確依照 `R-2001` 的波形數值繪製。
  - 10x10 的熱圖網格根據 `R-2001` 的二維陣列數據呈現顏色強弱。
  - AI 報告卡片顯示 `R-2001` 的診斷文字與指標。
- **允許偏差**：無

#### 測試情境 3：無紀錄空狀態
- **輸入**：選取一個完全沒有任何錄音紀錄的病患（例如新新增且尚未錄音的病患）。
- **預期輸出**：紀錄選擇器變為不可用，圖表區域顯示「請先為該病患進行腸音採集」的精緻引導提示。
- **允許偏差**：無

## 禁止事項
- 禁止寫死單一圖表，切換不同病患紀錄時，圖表波形與熱圖必須能夠動態更新。
