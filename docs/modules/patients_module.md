# patients_module 需求規格

## 負責檔案
- `app/patients.tsx`
- `styles/patients.styles.ts`

## 功能描述
本模組實作「病患管理」功能頁面。使用者可以瀏覽病患清單、透過關鍵字進行搜尋篩選、新增病患，並檢視每位病患的詳細資訊與歷史檢測列表。

## 輸入 / 輸出
- **輸入**：
  - 從 `AppContext` 讀取的 `patients` 列表與 `records` 歷史紀錄。
  - 使用者在搜尋欄輸入的文字。
  - 新增病患表單輸入值（姓名、年齡、性別、臨床備註）。
- **輸出**：
  - 渲染病患列表畫面與歷史記錄子視窗/卡片。
  - 呼叫 `addPatient` 修改全域資料。

## 相依模組
- `context_module` (`context/AppContext.tsx`)

## 實作要求
1. **病患列表與搜尋**：
   - 頂部提供搜尋框（Search Bar），使用者輸入姓名或 ID 時，能即時篩選下方清單。
   - 列表項目以卡片形式展示，包含頭像佔位符、病患姓名、ID（如 `P-1001`）、年齡、性別（男/女）。
2. **新增病患表單**：
   - 提供「新增病患」按鈕，點擊彈出 Overlay/Modal。
   - 表單包含：姓名、年齡（限數字）、性別單選（男/女）、備註文字區塊。
   - 提供基本欄位驗證（如姓名不可為空、年齡大於 0）。
   - 送出後，呼叫 context 中的 `addPatient`，並自動關閉彈窗並重新整理列表。
3. **病患詳情與檢測歷史**：
   - 點選清單中的病患卡片後，展開或跳轉展示病患的詳情，並在下方以時間倒序展示該病患的**所有腸音採集紀錄列表**。
   - 紀錄項目顯示：採集日期（格式化如 `YYYY/MM/DD HH:mm`）、錄音時長、AI 診斷結果狀態與標籤顏色（例如：正常為綠色、亢進為紅色、減弱為橙色）。

## 測試要求

### 測試工具
- React Native 測試工具，或透過 Expo Go 手動在介面上進行交互操作驗證。

### 測試情境

#### 測試情境 1：病患清單搜尋篩選
- **輸入**：在搜尋框中輸入 `"P-1001"` 或對應病患姓名。
- **預期輸出**：清單中僅保留 ID 為 `P-1001` 或姓名相符的病患卡片，其餘病患被過濾隱藏。
- **允許偏差**：無

#### 測試情境 2：新增病患與即時列表更新
- **輸入**：點選「新增病患」按鈕，輸入姓名 `"李四"`、年齡 `"30"`、性別 `"女"`、備註 `"無"`，並點選確定。
- **預期輸出**：
  - 彈窗成功關閉。
  - 清單底部或頂部即時新增一筆「李四」的病患卡片，ID 為 `P-1004`。
- **允許偏差**：無

#### 測試情境 3：病患歷史採集紀錄展示
- **輸入**：點選病患 `P-1001` 的卡片。
- **預期輸出**：展開其詳細區域，並正確列出該病患所關聯的全部檢測紀錄（對應 records 中 `patientId` 等於 `'P-1001'` 的所有項目）。
- **允許偏差**：無

## 禁止事項
- 禁止將狀態直接寫死在 `patients.tsx` 元件內而不提交給 Context，否則其他頁面（如即時採集）將無法選取新新增的病患。
